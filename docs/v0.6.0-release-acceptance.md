## What this acceptance does not show

- **Single sample.** It is one LOW, Worker-only build on one small disposable repository. It ran:
  - no Lead or Reviewer model turn;
  - no adjudication or correction.

  The finding → adjudication → correction → re-review route is still not observed end to end in one production build.
- **Lead model identity.** The Lead's model (`claude-opus-5-5` on 2.1.296) was attested only by doctor's init readback.
  No Lead model turn ran in this acceptance.
- **Model availability.** It shows that Claude Code 2.1.296 and this subscription served `claude-haiku-4-5-20251001` on
  2026-10-10, nothing later. If upstream stops serving it, the Worker fails closed (`model_identity`). Moving to another
  model is a configuration change that this evidence does not validate.
- **No new isolation claim:**
  - there is still no OS filesystem boundary for host provider CLIs;
  - Gate #2 is not run;
  - there is no Windows verification-isolation acceptance authority.
- **Writer gate unchanged.** `REAL_WRITER_LIVE_GATE_AUTHORIZED` stays `false` in code, and unattended Writer mode stays
  off.
