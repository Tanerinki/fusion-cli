# v0.6 — Hyper-V worker VFP/HNS ACL plan + the single elevated maintainer run

**Status: harness implemented (deterministic parts CI-proven); the live boundary is NOT run here. Architecture decision:
KEEP the TCP + HNS/VFP design (the named-pipe/no-adapter alternative is explicitly NOT adopted). Nothing in this document
is evidence that the boundary holds — only the elevated live run on the maintainer's host produces that. Until then:
`BROKER_ONLY_NETWORK_BOUNDARY = NOT_PROVEN`, `READY_FOR_GATE_2 = NO`.**

This continues `docs/v0.6-hyperv-poc-plan.md` with the concrete, now-selected stack (Docker Windows engine +
`--isolation=hyperv`) and the exact endpoint-ACL mechanism this machine actually exposes.

## 1. What the exploratory baseline established (no ACL)

A Hyper-V-isolated worker on a Docker `internal` network, with **no ACL**, could open TCP to unrelated services on the
host vNIC IP (RDP 3389, VMMS 2179, SMB, PostgreSQL) and the gateway answered DNS. A Docker `internal`/ICS network alone
is therefore **not** a boundary, and a raw socket (ignoring `HTTPS_PROXY`) bypasses any proxy. Docker's Windows driver
only creates NAT/QoS/OutboundNat/DisableICC policies — never an arbitrary egress ACL — so the ACL must be applied to the
worker's HNS **endpoint** directly, after the container starts.

## 2. Network-type finding (reported BEFORE any host change)

- **`internal` (Internal vSwitch, selected):** no external route, so LAN / Internet / the direct provider endpoint are
  denied **structurally** (there is no path off the host subnet). That leaves a **small, well-scoped** job for the ACL:
  deny the *same-subnet host ports* (RDP/VMMS/SMB/…) and *gateway DNS*, allowing only `brokerIp:brokerPort`. This is the
  smallest surface to enforce and is the chosen PoC network.
- **`nat`:** VFP-backed (port mappings prove VFP is attached), so endpoint ACLs *can* exist — but it grants the worker
  outbound Internet by default, enlarging what the ACL must deny; preferred only if `internal` + endpoint ACL cannot be
  made enforceable.
- **`l2bridge` / `transparent`:** also VFP-capable but require binding a **physical NIC** / a dedicated external vSwitch —
  a broader, more disruptive host change. Out of scope for this bounded PoC unless `internal` and `nat` both fail.

**Whether VFP actually honours an endpoint ACL on an `internal`-driver endpoint under Hyper-V isolation on this build is
the exact thing the live run must prove.** It is `NOT_PROVEN` and is not inferred from rule presence. If the live run
shows the ACL is not honoured on `internal`, the smallest next type to try is `nat` (endpoint ACL, deny-all-but-broker);
that is reported, not silently switched.

## 3. The endpoint ACL (built by the pure, CI-tested `acl-policy.mjs`)

The broker-only boundary is two **endpoint-scoped VFP rules** (`RuleType = "Switch"`), highest-precedence first (in VFP a
numerically smaller `Priority` wins):

| # | Action | Dir | Protocol | Remote address | Remote port | Priority |
| - | --- | --- | --- | --- | --- | --- |
| 1 | Allow | Out | TCP (6) | `brokerIp/32` | `brokerPort` | 100 |
| 2 | Block | Out | all | all | all | 200 |

Rule 2 carries no address/port/protocol, so it also denies **UDP/53 DNS to the gateway**, other ports on the broker's own
host IP, the LAN, the Internet, and the direct provider endpoint. The only hole is the single allow.

Submitted via the HCN API (this host has `computenetwork.dll` but **not** the `HostComputeNetwork` PowerShell module, and
the legacy `HostNetworkingService` module's `Invoke-HnsRequest` is not even exported — so `apply-acl.ps1` P/Invokes
`HcnModifyEndpointSettings`; the `hns.1` COM `Request2` path is the documented fallback). The exact JSON (as emitted):

```json
{ "ResourceType": "Policy", "RequestType": "Update", "Settings": { "Policies": [
  { "Type": "ACL", "Settings": { "Action": "Allow", "Direction": "Out", "RuleType": "Switch", "Priority": 100,
      "Protocols": "6", "RemoteAddresses": "10.250.37.1/32", "RemotePorts": "47610" } },
  { "Type": "ACL", "Settings": { "Action": "Block", "Direction": "Out", "RuleType": "Switch", "Priority": 200 } }
] } }
```

**Why endpoint-scoped, not a machine firewall rule.** A per-endpoint VFP ACL filters exactly one container's virtual
switch port; it touches no `Get-NetFirewallRule`, no profile, no other endpoint. It also cannot outlive the endpoint:
when the worker container is removed, its endpoint — and this ACL — ceases to exist. There is **no persistent, global host
object to roll back**. A broad `netsh`/firewall rule would be the opposite of this and is not used.

## 4. The single elevated maintainer run

```powershell
# ELEVATED PowerShell, Docker Desktop in Windows-engine mode:
powershell -NoProfile -ExecutionPolicy Bypass -File tools\hyperv-poc\elevated-run.ps1
# (optional overrides: -RunId <id> -BrokerIp 10.250.37.1 -Subnet 10.250.37.0/24 ; -KeepResources to skip auto-cleanup)
```

It is self-contained and **always cleans up in a `finally` block**. It: preflights (admin + Docker Windows engine +
isolation), builds `fusion-hv-poc-img:<RunId>` (nanoserver + node.exe + the canary), provisions the network + listeners,
starts the isolated worker, discovers its endpoint, applies the ACL, runs the canary before+after the ACL with host
positive controls, exercises broker I/J, checks process/forced-kill/stale cleanup, writes `result-<RunId>.json`, and runs
`verify.mjs` for the computed verdict.

### Exactly what it creates or modifies (all prefixed; `<RunId>` is per-run)

| Object | Name | Lifetime / revert |
| --- | --- | --- |
| Docker image | `fusion-hv-poc-img:<RunId>` | removed by cleanup (`docker rmi`) |
| Docker/HNS network (Internal vSwitch) | `FusionV06Poc-<RunId>-net` (+ its `vEthernet (…)` host vNIC at `10.250.37.1`) | removed by cleanup (`docker network rm`); the vNIC disappears with it |
| Worker container + its HNS endpoint | `FusionV06Poc-<RunId>` | removed by cleanup (`docker rm -f`); **the endpoint + ACL die with it** |
| Endpoint ACL (VFP) | on the worker endpoint id (a per-run GUID, discovered and printed) | not a standalone object; gone when the endpoint is removed |
| Host listener jobs | `FusionV06Poc-<RunId>-{broker,wrongport,hostother,provider}` | `Stop-Job`/`Remove-Job` by cleanup |
| Temp build context | `%TEMP%\FusionV06Poc-<RunId>-imgctx` | removed in `build-worker-image.ps1` finally |
| Evidence JSON (kept) | `prestate/provision/acl/inspect/endpoints/result-<RunId>.json` | retained for review (gitignored) |

The exact HNS network id (`com.docker.network.windowsshim.hnsid`) and the discovered **worker endpoint id** are printed by
the run and recorded in `result-<RunId>.json` (`policy.networkId`, `policy.workerEndpointId`). The ACL is applied **only**
to that discovered endpoint; if discovery is not unique (NONE/AMBIGUOUS/MALFORMED), the run applies nothing and records
INCOMPLETE.

### Rollback / Ctrl+C / failure

- **Rollback** = remove the Fusion-owned container/network/image/jobs/tempdir. `cleanup.ps1 -RunId <id>` does exactly that
  and only that (strict `FusionV06Poc-<RunId>` / `fusion-hv-poc-img:<RunId>` prefix match — mirrors the unit-tested
  `isPocResource`). There is no global firewall/route/DNS/switch change to undo.
- **Failure** → the `finally` block runs cleanup then inspect, and the script rethrows. Any partial evidence remains in
  `result-<RunId>.json`.
- **Ctrl+C** → PowerShell runs the `finally` on a pipeline stop in the common cases; because every resource is ephemeral
  and prefix-scoped, if cleanup is interrupted too, re-running `cleanup.ps1 -RunId <id>` (idempotent) fully reverts. The
  worker is `--rm`, so a killed engine/host also drops it.

### Proof unrelated resources are untouched

`prestate-<RunId>.json` captures the Docker network list and host adapter names **before** provisioning; cleanup removes
only prefixed names; `inspect.ps1` after cleanup must show nothing. A diff of the adapter/network lists back to the
prestate is the mechanical check (as in the exploratory baseline, where the adapter count returned to its original value
and no `10.250.37.x` address remained). The ACL never leaves the worker endpoint, so no firewall/route table changes.

## 5. The adversarial canary matrix (A–J) and how each is PROVEN

Every negative is proven with a **host positive control**: the trusted host attempts the identical target. A worker
*timeout* is promoted to a proven DENY **only** if the host control reached the target (service is up, worker can't →
isolation). A worker timeout with no host control is **INCOMPLETE, never PASS**. A forbidden target the worker *reaches*
is **FAIL**. (Logic: `evaluator.networkVerdict`, unit-tested.)

| | Canary | Target | Expected | How proven |
| - | --- | --- | --- | --- |
| A | ALLOWED_BROKER | `brokerIp:47610` | ALLOWED | worker connects + token echo; host control connects |
| B | WRONG_BROKER_PORT | `brokerIp:47611` | DENIED | worker blocked; host control connects (service up) |
| C | HOST_LOCALHOST | `127.0.0.1:47610` | DENIED | worker's own loopback, isolated from the host |
| D | HOST_OTHER_PORT | `brokerIp:47620` | DENIED | worker blocked; host control connects |
| D′ | HOST_OTHER_ADDRESS | other host IP:47620 | DENIED | worker blocked; host control connects |
| E | LAN_BYPASS | a LAN IP:80 | DENIED | structural (no route) + host control |
| F | DIRECT_INTERNET | `1.1.1.1:443` | DENIED | structural (no route) + host control |
| G | DIRECT_PROVIDER | provider stand-in `brokerIp:47630` | DENIED | worker blocked; host control connects |
| H | RAW_SOCKET_BYPASS | provider stand-in, raw TCP w/ proxy env set | DENIED | identical to G but asserted while `HTTPS_PROXY` is set |
| I | BROKER_PROVIDER_ROUTE | broker → provider stand-in | ALLOWED | production broker CONNECT-tunnels (reuses `provider-broker.ts`) |
| J | UNAUTHORIZED_DEST_THROUGH_BROKER | broker → wrong port | DENIED | production broker returns 403 |

No real AI provider is called; all endpoints are synthetic. (E/F may legitimately return INCOMPLETE if the host itself
cannot reach the chosen LAN/Internet target to establish a control — that is reported honestly, not forced to PASS.)

## 6. Also re-proven by the run (not inherited from AppContainer)

`noBroadHostMount` and `noDockerPipe` are structural and checked from the worker argv (`argv.mjs` forbids `-v`/`--mount`/
npipe/`docker_engine` — unit-tested); the worker env is host-constructed discrete `-e` pairs; the only secret-shaped
material is a **synthetic** per-run token (never a real credential); process-tree / forced-kill / stale-resource cleanup
are checked by killing the worker and confirming no surviving container/endpoint; host-workspace non-contamination holds
because the worker has no host bind mount. The filesystem view/scratch confinement (primary/sibling/control-plane/host-
profile denial) is a **separate** combined proof and is **not** claimed by this network PoC — so the full
`HYPERV_POC` verdict stays INCOMPLETE even if the network verdict passes.

## 7. Gate semantics

`verify.mjs` prints two verdicts: the focused **network** verdict (drives `BROKER_ONLY_NETWORK_BOUNDARY`) and the full
`HYPERV_POC` verdict (network + filesystem + lifecycle). Only a focused-network **PASS** — every A–J proven, no timeout
promoted — may set `BROKER_ONLY_NETWORK_BOUNDARY = PROVEN`. Even then, this stops for an evidence review; a real-provider
Gate #2 is a separate authorization. Until the live run passes: `BROKER_ONLY_NETWORK_BOUNDARY = NOT_PROVEN`,
`READY_FOR_GATE_2 = NO`.
